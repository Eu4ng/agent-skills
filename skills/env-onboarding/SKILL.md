# 환경 온보딩

공용 스킬은 특정 PC 의 서버 주소나 계정을 알지 못한다. 그런 정보는 PC 마다 **로컬 파일 하나**
`~/.agents/environment.md` 에 모으고, 스킬과 전역 지침은 이 파일을 읽는다.

- git 에 올리지 않는다. 네트워크 정보와 키 위치는 민감하다. 권한은 `600` 으로 둔다.
- 다른 PC 로 옮길 때는 이 파일만 복사하고, 점검 모드로 그 PC 에 맞게 고친다.
- 비밀값은 적지 않는다. 값이 있는 위치와 꺼내는 명령만 적는다.
- 진입점만 적는다: 호스트, 접속 경로, kubectl 실행 명령, 저장소, 시크릿 위치. 서비스 목록처럼 붙으면 바로
  조회할 수 있는 정보는 적지 않는다. 적어 두면 곧 틀린다.

다른 요청(예: "서버 목록 알려줘", "클러스터에 배포해 줘")을 처리하다가 이 스킬로 온 경우에는 먼저 "환경 정보
파일이 없어(또는 틀려서) 온보딩부터 한다"고 한 줄로 알린다. 온보딩이 끝나면 원래 요청으로 돌아간다.
아래 명령의 `scripts/`, `assets/` 경로는 이 스킬 폴더 기준이다.

## 빠른 절차

1. **질문하기 전에 먼저 감지 스크립트를 실행한다**: `python3 scripts/detect.py`
2. 결과의 `agents.environment.exists` 를 본다.
   - 참이면: 파일을 읽고 아래 4단계(점검)를 한다.
   - 거짓이면: 감지 결과(ssh 설정의 Host, 저장소, 게이트웨이)를 사용자에게 보여 준다. 그리고 아래 2단계의 질문
     목록을 **한 번에** 묻는다. 감지로 알게 된 것은 묻지 않는다.
3. 답을 받으면 `assets/environment.template.md` 형식으로 `~/.agents/environment.md` 를 쓰고 `chmod 600` 한다.
4. 원래 요청으로 돌아가 파일의 정보로 처리한다.

## 절차 (자세히)

1. **상태를 보고 감지한다.** 읽기만 하므로 묻기 전에 먼저 한다.

   ```bash
   python3 scripts/detect.py --repo-root <저장소를 두는 폴더(모르면 생략하면 홈 전체)>
   ```

   `agents.environment.exists` 가 참이면 4단계(점검)로 간다. 거짓이면 ssh 설정의 Host 항목, 공개 키 코멘트,
   저장소 remote, 기본 게이트웨이, 설치된 명령으로 템플릿 칸을 먼저 채운다.
2. **한 번에 모아서 묻는다.** 질문은 이 한 번으로 끝낸다.
   - 다른 PC 나 백업(NAS 등)에 이미 만든 environment.md 가 있는지. 있으면 그것을 `~/.agents/environment.md` 로
     복사하고 `chmod 600` 한 뒤 4단계로 간다. 새로 만드는 것보다 빠르고 정확하다. 아래 항목은 답하지 않아도 된다고
     함께 알린다.
   - 관리하는 서버의 주소·접속 계정·역할(가상화 호스트, 클러스터 노드 등)
   - 클러스터별 kubectl 을 어디서 실행하는지
   - LAN 밖에서 접속하는 경로(터널, VPN, 점프 호스트)
   - 쓰는 도메인과 인증 방식
   - 실행 전에 확인받아야 하는 작업

   감지 결과로 이미 알게 된 것은 묻지 않고 "이렇게 감지했다"고 보여 준다.
3. **서버에서 채우고 파일을 쓴다.** 서버에 접속할 수 있게 되면 나머지는 서버에서 조회한다. 사용자에게 묻지 않는다.
   예:
   - 클러스터 시크릿의 이름과 키(`kubectl get secret -A`, 값은 보지 않는다)
   - GitOps 저장소 구조
   - 각 서버의 역할

   [assets/environment.template.md](assets/environment.template.md) 형식으로 파일을 쓰고 `chmod 600` 한다.
   모르는 칸은 비우지 말고 `확인 필요` 로 둔다.
4. **점검한다.** 파일에 적힌 접속 대상을 모두 시험한다. 현재 네트워크에 맞는 경로(LAN 안·밖)를 고른다.

   ```bash
   python3 scripts/detect.py --only network,probe --probe <user@host> --probe <user@host> ...
   ```

   - 실패한 항목은 원인을 보고 고친다. 키 미등록, 호스트 키 불일치, LAN 밖 등이 원인일 수 있다.
     고칠 수 없으면 사용자에게 알린다.
   - 저장소 경로가 있는지, 적힌 kubectl 위치에서 `kubectl get nodes` 가 되는지 확인한다.
   - 틀린 항목만 고치고 `갱신:` 날짜를 바꾼다.
5. **전역 지침에 연결한다.** `~/.agents/AGENTS.md`(도구 공통 전역 지침)에 아래 줄이 없으면 더한다. 파일이 없으면
   이 줄로 새로 만든다.

   ```markdown
   환경 정보(서버, 접속 경로, 클러스터, 저장소, 시크릿 위치)는 `~/.agents/environment.md` 에 있다. 서버·클러스터·저장소 작업 전에 읽고, 없거나 틀리면 고친다.
   ```

   서버 주소 같은 환경 정보가 AGENTS.md 에 직접 적혀 있으면 environment.md 로 옮기고 AGENTS.md 에서는 지운다.
6. **도구별 전역 지침 위치를 확인한다.** 공통 파일을 직접 읽지 않는 도구는 자기 위치의 파일만 읽는다.
   `detect.py` 의 `agents` 절에서 설치된 도구의 전역 지침이 `~/.agents/AGENTS.md` 를 가리키는지 본다. 가리키지
   않으면 링크를 제안하고, 동의하면 만든다.

   | 도구 | 전역 지침 위치 |
   | :--- | :--- |
   | Claude Code | `~/.claude/CLAUDE.md` |
   | Codex CLI | `~/.codex/AGENTS.md` |
   | Gemini CLI | `~/.gemini/GEMINI.md` |

   기존 파일이 링크가 아닌 일반 파일이면 내용을 `~/.agents/AGENTS.md` 에 합친 뒤 링크로 바꾼다. 지우기 전에
   사용자에게 확인한다.
7. **보고한다.** 만든·고친 항목, `확인 필요` 로 남은 항목, 접속 실패 항목을 짧게 알린다. 원하면 이 파일을
   백업 대상(NAS 등)에 넣으라고 제안한다.

## 주의

- ssh 접속 시험은 반드시 `BatchMode=yes` 로 한다. 비밀번호나 호스트 키 확인 창이 뜨면 에이전트가 멈춘다.
  `detect.py --probe` 가 이렇게 한다.
- 처음 붙는 호스트는 호스트 키 확인 때문에 실패한다. 호스트 키 지문을 사용자에게 보여 주고 확인받은 뒤에
  `ssh-keyscan` 결과를 `known_hosts` 에 더한다.
- 사용자가 비밀값을 대화에 붙여 넣어도 파일에는 쓰지 않는다. 그 값을 둘 안전한 위치를 정하고, 파일에는 위치만 적는다.
  안전한 위치의 예: 클러스터 시크릿, 권한 600 인 로컬 파일, 비밀번호 관리자.
- 같은 사람의 PC 라도 네트워크 위치와 키가 다르다. 다른 PC 에서 가져온 파일은 반드시 4단계로 점검한다.

## 스크립트

- `scripts/detect.py`: 표준 라이브러리만 쓴다. 비밀값은 읽지 않는다.
  - OS·도구·ssh 설정·공개 키·저장소·네트워크·지침 파일을 JSON 으로 낸다.
  - `--probe` 로 ssh 접속을 시험한다.
  - `--help` 참고.

## 하지 않는 것

- environment.md 를 git 저장소 안에 두거나 커밋하지 않는다.
- 개인 키, 토큰, 비밀번호 내용을 읽어 출력하거나 파일에 적지 않는다.
- 사용자 확인 없이 기존 전역 지침 파일을 지우거나 덮어쓰지 않는다.
