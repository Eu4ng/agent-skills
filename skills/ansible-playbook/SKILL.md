# Ansible 플레이북

플레이북은 "다시 실행해도 결과가 같고(멱등), 새 서버에서도 저장소만으로 같은 상태를 만드는" 코드여야 한다. 그래서 값은 변수 파일
한 곳에만 두고, 실행한 뒤에는 **한 번 더 실행해 바뀐 것이 없는지(changed≈0)** 확인한다.

## 환경 정보

`~/.agents/environment.md` 의 `## 저장소`(플레이북 저장소 위치)와 `## 시크릿 위치`(API 토큰 파일 등) 절을 직접 열어 읽는다(있는지 사용자에게
묻지 않는다). 파일이 없거나 필요한 항목이 비어 있으면 먼저 접근 가능한 곳(설정 파일, 서버, 저장소)을 조사하고, 그래도 모르는 것만
사용자에게 묻는다. 알아낸 값은 그 파일의 해당 절에 적은 뒤 진행한다. 비밀값 자체는 적지 않고 값이 있는 위치만 적는다.

## 절차

1. **환경 정보와 저장소 규칙을 읽는다**: 저장소의 `README.md`·`AGENTS.md` 에서 실행에 필요한 환경 변수(API 토큰 등)와 변수 파일 위치
   (보통 `group_vars/all.yml`), 인벤토리 구조를 확인한다.
2. **고친다**:
   - 값(IP, VMID, 크기, 버전)은 변수 파일에만 두고, 플레이북·템플릿은 변수만 참조한다. 한 값이 두 곳에 있으면 안 된다.
   - 모듈이 있으면 모듈을 쓴다. 셸 명령이 필요하면 멱등하게 쓴다: 이미 된 상태면 `exit 0`, 바꿨을 때만 `CHANGED` 를 출력하고
     `changed_when: "'CHANGED' in r.stdout"` 로 판정한다.

     ```yaml
     - name: 예시 (없을 때만 설정)
       ansible.builtin.shell: |
         <현재 상태 확인> && exit 0
         <바꾸는 명령>
         echo CHANGED
       register: r
       changed_when: "'CHANGED' in r.stdout"
     ```

   - 비밀값은 저장소 밖 파일에서 읽어 명령 안에서만 쓰고, 그 작업에 `no_log: true` 를 둔다.
   - 새 호스트를 만들었으면 인벤토리에도 넣는다(이름 기반 DNS·공통 설정 플레이북이 인벤토리를 읽는 경우가 많다).
3. **문법을 검사한다**: `ansible-playbook --syntax-check playbooks/<파일>.yml`
4. **실행한다**: 필요한 환경 변수를 비밀 파일에서 채워 실행하고, 출력은 파일로 남겨 실패·변경을 찾는다.

   ```bash
   ansible-playbook playbooks/<파일>.yml > /tmp/run.log 2>&1
   grep -E 'fatal|FAILED' /tmp/run.log; sed -n '/PLAY RECAP/,$p' /tmp/run.log
   ```

   `failed=0` 이 아니면 `grep -B2 -A12 fatal /tmp/run.log` 로 원인을 보고 고친 뒤 다시 실행한다.
5. **다시 실행한다**: 같은 명령을 한 번 더 돌려 `changed` 가 0(또는 "매번 changed 로 보고됨"이라 적힌 작업만)인지 확인한다.
   0 이 아닌 작업은 실제로 무엇을 바꿨는지 대상 시스템에서 확인한다(모듈이 바꾼 것 없이 changed 를 보고하는 경우도 있다).
6. **검증**: 대상 시스템에서 결과(서비스 응답, 설정 값)를 직접 확인하고, README 의 플레이북 설명을 함께 고친 뒤 보고한다.

## 주의

- 재시작이 필요한 변경(VM 메모리, 컨테이너 장치 등)은 플레이북이 적용만 하고 재시작하지 않을 수 있다. 재시작이 서비스에 영향을 주면
  사용자 확인을 받는다.
- 블록 표식(`blockinfile` 의 `marker`) 문자열을 바꾸면 대상 파일에 같은 블록이 하나 더 들어간다. 이름이 낡아도 그대로 두고 주석으로 이유를 남긴다.
- 파이프(`| tail`)로 출력을 자르면 "Non-blocking file handles" 오류가 날 수 있다. 출력은 파일로 받은 뒤 읽는다.

## 하지 않는 것

- 대상 서버에서 손으로 바꾸고 플레이북은 고치지 않은 채 끝내지 않는다.
- 비밀값을 변수 파일·인벤토리·로그에 남기지 않는다.
