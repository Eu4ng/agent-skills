# 하위 에이전트 위임

Agent Skills 표준은 스킬 형식만 정하고, 하위 에이전트(서브에이전트) 정의 형식은 정하지 않는다. 도구마다
위임 기능의 유무와 설정 위치가 다르다. 그래서 역할을 **그 역할을 쓰는 스킬 안의 지시문 파일**로 둔다.

- 위임할 수 있는 도구는 이 파일을 하위 에이전트에게 지시문으로 넘긴다.
- 위임할 수 없는 도구는 같은 지시문을 스스로 순서대로 수행한다.

결과는 같고 속도와 맥락 사용량만 다르다.

## 언제 위임하는가

- **넓은 탐색**: 많은 파일, 긴 로그, 여러 저장소를 훑고 결론만 필요할 때. 원문이 주 맥락을 채우지 않는다.
- **서로 독립인 병렬 작업**: 여러 대상에 같은 조사·검증을 할 때. 각 작업이 서로의 결과를 기다리지 않아야 한다.
- **새 맥락에서의 검증**: 작성한 쪽의 가정에 물들지 않은 눈으로 결과를 점검할 때.

한두 번의 명령이나 파일 하나를 읽으면 끝나는 일은 위임하지 않는다. 지시문을 쓰고 결과를 읽는 비용이 더 크다.

## 역할 파일 형식

`references/<역할>.md` 에 둔다. 하위 에이전트는 대화 맥락을 모른다고 가정하고, 파일만 읽고 일할 수 있게 쓴다.

```markdown
# 역할: <이름>

- 맡기는 때: <어떤 상황에서 이 역할을 부르는가>
- 넘길 입력: <대상 경로, 질문, 기준 등 호출할 때 채워 넣을 값>
- 권한: <읽기 전용 | 쓰기 허용 범위(폴더·파일)>
- 돌려받을 형식: <짧은 요약 | JSON 스키마 | 표. 원문을 그대로 붙이지 않게 한다>
- 위임할 수 없을 때: 아래 지시문을 직접 순서대로 수행한다.

## 지시문

<하위 에이전트에게 그대로 넘길 본문. 목표, 절차, 판단 기준, 하지 않을 것, 출력 형식을 담는다.>
```

## SKILL.md 에서 부르는 법

해당 단계에 한 줄로 쓴다.

```markdown
3. **자료 조사**: 하위 에이전트를 띄울 수 있으면 `references/researcher.md` 를 지시문으로 넘겨 맡기고,
   아니면 그 지시문대로 직접 한다.
```

## 병렬 위임 원칙

- 쓰기 작업을 병렬로 맡길 때는 대상 파일·폴더가 겹치지 않게 나눈다. 겹치면 한 역할로 합치거나 순서대로 돌린다.
- 병렬 역할은 모두 같은 형식으로 결과를 돌려주게 해서 합치기 쉽게 한다.
- 되돌리기 어려운 작업(삭제, push, 배포, 원격 서버 변경)은 위임하지 않고 주 에이전트가 확인한 뒤 한다.
- 하위 에이전트의 결과는 주장이다. 중요한 결론은 주 에이전트가 원문이나 명령으로 한 번 더 확인한다.
