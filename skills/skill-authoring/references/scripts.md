# 스킬 스크립트 설계

에이전트가 부르는 스크립트의 규칙이다. 에이전트는 stdout·stderr 를 읽고 다음 행동을 정하므로, 사람보다 에이전트가
쓰기 좋게 만든다.

## 언제 스크립트로 만드는가

- 평가 기록을 보니 에이전트가 같은 코드를 매번 새로 짠다.
- 명령이 길고 틀리기 쉽다(옵션 조합, 순서, 따옴표).
- 결과를 기계적으로 검사해야 한다(검증기, 린터).

한두 줄 명령이면 `SKILL.md` 에 그대로 쓴다.

## 규칙

- **비대화형**: 입력 프롬프트, 비밀번호 창, 확인 메뉴를 쓰지 않는다. 에이전트는 응답할 수 없어 멈춘다. 입력은
  인자·환경 변수·stdin 으로 받고, 없으면 무엇이 필요한지 알려 주고 끝낸다.
- **`--help`**: 용도, 옵션, 예시 2개 이상, 출력 형식, exit code 를 적는다. 에이전트가 사용법을 배우는 곳이다.
- **출력**: 결과 데이터는 stdout 에 JSON(또는 JSON Lines)으로, 진행·경고·오류는 stderr 로 낸다.
- **출력 크기**: 도구 출력은 흔히 잘린다. 요약을 기본값으로 하고 `--limit`, `--output <파일>` 로 더 받게 한다.
- **오류 메시지**: 무엇이 잘못됐는지, 무엇을 기대했는지, 어떻게 고치는지 쓴다.
  예: `오류: --format 은 json, csv 중 하나다. 받은 값: xml`
- **exit code**: 0 성공, 1 실행 실패, 2 사용법 오류. 그 밖의 코드는 `--help` 에 적는다.
- **멱등**: 에이전트는 실패하면 다시 실행한다. "없으면 만든다", "같으면 건너뛴다"로 만든다.
- **dry-run**: 상태를 바꾸는 스크립트에는 `--dry-run` 을 둔다. 되돌릴 수 없는 작업은 명시적 플래그가 있을 때만 한다.
- **비밀값**: 인자로 받지 않는다(프로세스 목록과 셸 기록에 남는다). 환경 변수나 파일 경로로 받고, 출력하지 않는다.
- **의존성**: 가능하면 표준 라이브러리만 쓴다. 오프라인과 다른 PC 에서도 바로 돌아간다. 필요하면 파일 머리에
  PEP 723 메타데이터로 적고 `uv run` 으로 부르되, 없을 때의 대체 방법을 `SKILL.md` 에 적는다.
- **경로**: `SKILL.md` 에서는 스킬 폴더 기준 상대 경로(`scripts/x.py`)로 가리킨다. 스크립트 안에서 스킬 파일을
  읽을 때는 `Path(__file__).resolve().parent` 기준으로 찾는다. 실행 위치에 기대지 않는다.

## SKILL.md 에 적는 법

```markdown
## 스크립트

- `scripts/check.py`: 배포 전 검사를 순서대로 돌리고 결과를 JSON 으로 낸다. `--help` 참고.
```

절차 단계에서는 정확한 명령을 쓴다.

````markdown
3. **검사한다.**

   ```bash
   python3 scripts/check.py --root <저장소>
   ```
````
