# 스킬 작성

스킬은 Agent Skills 표준 형식의 폴더 하나다(요점: [references/spec.md](references/spec.md)). 좋은 스킬의 기준은 셋이다.

- 어떤 에이전트 도구와 모델이 읽어도 같은 결과가 나온다.
- 작은 로컬 모델에서도 동작한다.
- 인터넷 없이도 동작한다.

아래 명령의 `scripts/`, `assets/`, `references/` 는 이 스킬 폴더 기준 경로다.

## 빠른 절차

1. **위치와 이름을 정한다. 묻지 않고 스스로 정한다.**
   - 위치: 여러 저장소·PC 에서 쓸 절차면 공용 스킬 저장소의 `skills/`, 한 저장소 전용이면 `<저장소>/.agents/skills/`.
   - 이름: 작업을 나타내는 영어 소문자·하이픈. 예: `release-tagging`.
   - 같은 스킬이 이미 있는지는 설치된 스킬 목록의 이름·설명만 보고 판단한다. 모든 SKILL.md 를 열어 보지 않는다.
     있으면 새로 만들지 않고 그 스킬을 고친다.
2. **뼈대를 스크립트로 만든다.** SKILL.md 를 손으로 처음부터 쓰지 않는다. 손으로 쓰면 frontmatter 형식이
   틀리기 쉽다.

   ```bash
   python3 scripts/new_skill.py <위치> <이름>
   ```

3. **`TODO(...)` 를 모두 채운다.** 만들어진 `<위치>/<이름>/SKILL.md` 를 읽고 고쳐 쓴다.
   - `description`: 언제 쓰는지와 쓰지 않는 경우
   - `## 절차`: 실제 명령을 포함한 단계
   - `## 절차` 마지막 단계: 검증 명령
   - `## 주의`: 사용자가 교정한 사실

   필요 없는 선택 절(환경 정보, 주의, 스크립트)은 통째로 지운다.
4. **검사한다.** 오류와 경고가 0 이 될 때까지 고치고 다시 실행한다. **검사를 통과하기 전에는 끝났다고 보고하지 않는다.**

   ```bash
   python3 scripts/lint.py <위치>/<이름>
   ```

5. **평가 사례를 만들고 로컬 모델로 점검한다.** `<위치>/<이름>/evals/triggers.json`, `evals/evals.json` 을 쓰고
   [references/evaluation.md](references/evaluation.md) 대로 돌린다. 로컬 모델 서버가 없으면 건너뛴다고 보고한다.
6. **등록한다.** 대상 저장소 AGENTS.md 의 규칙(README 표, 작업 표, 검사 명령, 커밋)을 따른다.

사용자에게는 되돌리기 어려운 결정만 묻는다(예: 공개 저장소에 올려도 되는 내용인지). 이름, 설명 문구, 절차 구성은
스스로 정하고 결과를 보고한다.

## 규칙

1. **근거에서 쓴다.** 일반론으로 쓴 스킬은 쓸모가 없다. 사용자의 교정, 성공한 명령 순서, git 이력, 기존 문서와
   스크립트에서 가져온다. 지난 세션 기록을 뒤져야 하면 [references/sources.md](references/sources.md) 를 읽는다.
2. **한 스킬은 한 작업 단위만 맡는다.** 저장소 전용 스킬의 절차가 여러 저장소에 필요해졌을 때만 공용으로 옮기고,
   원래 스킬에서는 그 부분을 뺀다. 한 절차가 두 곳에 있으면 안 된다.
3. **환경 고유값을 쓰지 않는다.** 호스트, IP, 사용자, 경로, 시크릿 위치, 도메인이 여기에 해당한다. 이런 값은
   `~/.agents/environment.md` 에서 읽게 한다. 템플릿의 `## 환경 정보` 절이 그 문구다. 절차의 첫 단계도 "환경 정보
   파일을 읽는다"로 둔다. 작은 모델은 절차에 없는 단계를 건너뛴다.
4. **frontmatter**:
   - `name`: 1~64자, `a-z`·`0-9`·`-` 만 쓴다. 폴더명과 같아야 한다.
   - `description`: 1024자 이내. `compatibility` 는 필요한 명령·런타임이 있을 때만 쓴다.
   - `allowed-tools` 는 쓰지 않는다.
   - 표준 전체는 [references/spec.md](references/spec.md).
5. **description 은 발동 여부를 정하는 유일한 근거다.**
   - "…할 때 쓴다"로 쓴다. 첫 문장은 작업 대상으로 좁게 시작한다(예: "파이썬(.py) 코드를…", "새 커밋을…").
   - 사용자가 도메인 단어를 말하지 않는 경우도 포함한다.
   - 헷갈리기 쉬운 작업만 "…에는 쓰지 않는다"로 짧게 적는다. 작은 모델은 설명 속 단어에 끌리므로 넓은 표현과
     긴 제외 목록을 피한다.
   - 다른 스킬 이름은 쓰지 않는다.
6. **본문**:
   - 에이전트가 이미 아는 일반 지식은 뺀다.
   - 기본값 하나와 예외 조건을 준다.
   - 순서가 중요하면 번호를 매기고, 깨지기 쉬운 작업은 정확한 명령을 쓴다. 규칙에는 이유를 한 구절 붙인다.
   - 작은 모델이 따라 할 수 있게 맨 앞에 명령 단위의 짧은 절차를 둔다.
   - `SKILL.md` 는 500줄 미만으로 유지한다. 긴 자료는 `references/` 로 옮기고 "X 할 때 읽는다"를 적는다.
     참조는 한 단계만 둔다.
7. **공급자 중립.**
   - 도구 이름 대신 동작으로 쓴다: "파일을 읽는다", "명령을 실행한다".
   - 제품·모델명을 쓰지 않는다. 주제가 그 제품일 때만 예외다.
   - 다른 스킬을 이름으로 부르지 않고, 할 일("커밋하고 push 한다")만 적는다.
8. **오프라인 동작.**
   - 스킬 안의 파일만으로 작업할 수 있어야 한다.
   - 필요한 외부 지식은 필요한 만큼만 `references/` 에 로컬 문서로 쓴다.
   - 웹 링크는 파일 끝 `## 참고` 절에 참고로만 둔다.
   - 도구·라이브러리 동작은 로컬 도움말(`--help`, `man`, `python3 -m pydoc`)로 확인하게 한다.
   - 처음 실행할 때 내려받는 도구(`uvx`, `npx` 등)를 쓰면 없을 때의 대체 명령을 함께 적는다.
9. **스크립트**:
   - 같은 코드를 매번 새로 짜게 되거나 명령이 길고 틀리기 쉬우면 `scripts/` 에 넣는다.
   - 검증 명령이 여러 개면 하나의 검사 스크립트로 묶는다. 작은 모델은 여러 명령 중 일부를 빠뜨리거나 실패를
     무시하고 끝낸다. 한 명령이 전체 결과를 `ok` 하나로 알려 주면 따르기 쉽다.
   - 비대화형으로 만들고 `--help` 를 둔다. 결과는 stdout 에 JSON 으로 낸다.
   - 멱등으로 만들고, 상태를 바꾸면 `--dry-run` 을 둔다.
   - 가능하면 표준 라이브러리만 쓴다.
   - 자세한 규칙은 [references/scripts.md](references/scripts.md).
10. **위임.** 표준에는 하위 에이전트 정의가 없다. 넓은 탐색, 독립 병렬 작업, 새 맥락 검증처럼 위임이 이득인 부분만
    역할 파일로 둔다. 형식은 [references/delegation.md](references/delegation.md).
11. **평가.** 평가 사례(`evals/`)는 스킬 안에 저장한다. 그래야 다른 모델로도 같은 점검을 되풀이할 수 있다.
    - 결과는 `local_eval.py --record` 로 `evals/results.json` 에 모델별로 남긴다.
    - 여러 모델에서 통과할수록 검증된 스킬이다.

## 기존 스킬 고치기

- 사용자에게 교정을 받으면 해당 스킬의 `## 주의` 에 한 줄로 더하고, 그 상황을 재현하는 사례를 `evals/` 에 더한다.
- 규칙을 더하기 전에 뺄 것부터 찾는다. 적용되지 않는 지시, 모호한 지시, 선택지가 많은 지시는 에이전트를 헤매게 한다.
- `name` 을 바꾸면 폴더명과, 그 이름을 가리키던 README·AGENTS.md 표도 고친다.

## 스크립트

- `scripts/new_skill.py`: 템플릿으로 새 스킬 폴더를 만든다.
- `scripts/lint.py`: 검사 항목은 두 가지다.
  - 표준 규칙: 이름, 길이, 폴더명
  - 이 스킬의 규칙: 남은 `TODO(`, 깨진 링크, 줄 수, 참조 깊이, 제품·도구 이름, 다른 스킬 이름, 비밀값·사설 IP,
    `## 참고` 밖의 웹 링크
- `scripts/local_eval.py`: 저사양 로컬 모델 서버로 트리거와 실행을 점검하고 결과를 기록한다.
- `scripts/user_messages.py`: 세션 기록(JSONL)에서 사람이 입력한 메시지만 뽑는다.

모두 표준 라이브러리만 쓴다. 쓰는 법은 각각 `--help`.

## 하지 않는 것

- 비밀값(토큰, 비밀번호, 개인 키)을 스킬에 쓰지 않는다. 값이 있는 위치를 찾는 방법만 적는다.
- 공개 저장소의 스킬에 개인 인프라 정보(IP, 호스트명, 도메인, 계정)를 넣지 않는다.
- 특정 도구 전용 폴더·파일이나 심볼릭 링크를 저장소에 만들지 않는다.
- 다른 스킬의 이름에 의존하는 지시를 쓰지 않는다.
