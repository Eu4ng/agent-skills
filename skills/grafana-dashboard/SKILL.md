# Grafana 대시보드

대시보드 수정은 JSON 이 바뀐 것으로 끝나지 않는다. 배포된 대시보드에서 모든 패널의 쿼리가 오류 없이 데이터를
돌려주는 것까지 확인해야 끝난다. 화면을 직접 볼 수 없으면 API 로 확인한 범위만 보고한다.
아래 `scripts/` 경로는 이 스킬 폴더 기준이다.

대시보드가 아니라 Grafana 서버 설정(시간대, 인증, 데이터소스, 플러그인 등 배포 values)을 바꾸는 일이면 이 스킬의
절차 대신 GitOps 변경 절차를 따른다. GitOps 변경을 다루는 스킬이 있으면 먼저 켠다.
저장소를 고쳐 커밋·push 한 뒤, 동기화 도구의 앱 리비전이 push 한 커밋 SHA 와 같고 Synced·Healthy 가 될 때까지 기다린다
(예: `<kubectl 실행 명령> -n argocd get app <앱> -o custom-columns=REV:.status.sync.revision,SYNC:.status.sync.status,HEALTH:.status.health.status`
을 반복). 그 전에 본 롤아웃·로그는 옛 배포다. 그다음 배포된 리소스에 새 값이 들어갔는지 확인한다.
설정 파일 위치는 사용자에게 묻지 말고 GitOps 저장소에서 찾는다.

## 환경 정보

`~/.agents/environment.md` 의 `## 서비스`(Grafana 주소, 관리자 자격 증명이 든 시크릿, 대시보드 원본 파일 위치)와
`## 클러스터` 절을 읽는다. 파일이 없거나 항목이 비어 있으면 먼저 접근 가능한 곳(설정 파일, 서버, 저장소)을 조사하고,
그래도 모르는 것만 사용자에게 묻는다. 알아낸 값은 그 파일의 해당 절에 적은 뒤 진행한다. 비밀값 자체는 적지 않는다.

## 빠른 절차

진단이나 계획만 보고하고 멈추지 않는다. 삭제처럼 확인이 필요한 작업이 아니면 고치기·배포·검증까지 이어서 하고, 끝난 뒤
한 번에 보고한다.

1. **환경 정보를 읽는다.** `cat ~/.agents/environment.md` 를 실행해 읽는다(있는지 사용자에게 묻지 않는다). 경로는 홈 폴더 아래 `.agents` 폴더 안이다. 읽기에 실패하면 경로를 다시 확인하고 `ls -a ~/.agents` 로 찾는다.
   그 파일에서 Grafana 주소, 관리자 자격 증명이 든 시크릿, kubectl 실행 명령, 대시보드 원본 파일 위치를 확인한다.
2. **지금 상태를 먼저 검사한다.** 고치기 전에 어떤 패널이 오류·빈 결과인지 본다. 패널 이름, 쿼리, 데이터소스,
   코드로 관리되는지는 사용자에게 묻지 않는다. 검사 결과와 원본 JSON 에서 찾는다.

   ```bash
   python3 <이 스킬 폴더>/scripts/panel_check.py --uid <대시보드 uid> --url <Grafana 주소> \
     --admin-secret <ns>/<시크릿 이름> --kubectl "<kubectl 실행 명령>"
   ```

   자격 증명은 `--admin-secret` 이 시크릿에서 직접 읽는다. 사용자에게 묻지 않고, 직접 꺼내 출력하거나 명령에 붙여 넣지 않는다.
   시크릿을 꺼내는 명령(`get secret ... | base64 -d`)은 실행하지 않는다.
   `--kubectl` 에는 환경 정보의 kubectl 실행 명령을 그대로 넣는다(예: `--kubectl "ssh cp kubectl"`). 스크립트가 실패하면
   출력의 오류를 보고 인자를 고친다. 스크립트를 두고 API 를 직접 부르지 않는다.
3. **원본 JSON 을 스크립트로 고친다.** 대시보드가 코드로 관리되면(GitOps 저장소에 대시보드 JSON 이 있으면) Grafana 화면이나
   API 로 대시보드를 받아 고치거나 저장하지 않는다. 저장소의 원본 파일을 고친다. 오류 패널의 `raw_sql`(원본 JSON 의 쿼리)을
   원본 파일에서 찾아(`grep -F`) 고친다. `sql` 은 변수가 풀린 쿼리라 원본에는 그대로 없다. 큰 JSON 은 문자열 치환 대신 `python3` 으로 읽고 고쳐 다시 쓴다. 같은 종류의 패널·변수가 여러 개면 전부
   같은 규칙으로 고친다. 고친 뒤에도 같은 오류가 나면 검사 결과의 `sql`(실제로 실행된 쿼리)과 `raw_sql` 을 비교해 원본 쿼리를 다시 고친다.
4. **배포한다.** 원본 저장소의 절차를 따른다. GitOps 면 커밋·push 하고, 동기화 도구가 새 커밋으로 Synced 가 될 때까지 기다린다.
5. **반영을 기다린 뒤 다시 검사한다.** 새 JSON 에만 있는 문자열로 배포 반영을 확인하고 전체 패널을 검사한다.

   ```bash
   python3 <이 스킬 폴더>/scripts/panel_check.py --uid <uid> --url <Grafana 주소> \
     --admin-secret <ns>/<시크릿 이름> --kubectl "<kubectl 실행 명령>" \
     --wait-contains "<새 JSON 에만 있는 문자열>" --wait 100
   ```

   반영 전에 대기가 끝나면(시간 초과) 같은 명령을 다시 실행한다. 사용자에게 기다려 달라고 넘기지 않는다.
6. **검증**: `counts.error` 가 0 이고, 데이터가 있어야 할 패널이 `empty` 가 아닐 때까지 고치고 다시 실행한다.
   통과하기 전에는 끝났다고 보고하지 않는다. 보고에는 "화면이 아니라 API 로 쿼리를 확인했다"고 밝힌다.

## 규칙

- **스키마를 그대로 보여 준다.** 확인용 대시보드는 DB 컬럼을 가공하지 않고 보여 준다. 새 컬럼이 자동으로 나타나게
  한다(`SELECT *`, 정보 스키마 조회, 값마다 반복 패널). 이름·단위를 대시보드에서만 바꾸는 가공은 요청받았을 때만 한다.
- **값의 종류에 맞는 패널을 쓴다.** 불리언·상태 값(on/off, true/false, online/offline, open/closed)은 시계열 그래프가
  아니라 상태 타임라인(`state-timeline`)으로 그린다. 시계열로 그리면 0~1 사이 소수로 보인다.
  - 판단은 속성 이름 목록이 아니라 값으로 한다. 예: 값 집합이 불리언 문자열뿐인 속성.
  - 참·거짓은 명도 차이가 큰 두 색으로 구분한다.
  - 기록이 끊긴 구간은 거짓처럼 이어지지 않게 빈 값을 넣는다.
- **관련 값은 한 패널에 모은다.** 같은 단위로 비교하는 값은 하나의 패널로 모은다(예: PM1·PM2.5·PM10).
- **시간대**를 사용자 시간대로 맞춘다. Grafana 전체의 기본 시간대는 서버 설정(`[date_formats] default_timezone`,
  환경 변수로는 `GF_DATE_FORMATS_DEFAULT_TIMEZONE`)이고, 대시보드 JSON 의 `timezone` 은 그 대시보드만 바꾼다.
  "기본 시간대"를 바꾸라는 요청은 서버 설정을 바꾼다.

## "No data" 원인 찾기

| 원인 | 확인·해결 |
| :--- | :--- |
| 반복 패널에서 변수가 따옴표 없이 들어가 `column "x" does not exist` | 반복 값은 하나로 따옴표 없이 들어간다. 변수 설정이 아니라 패널 쿼리(`rawSql`)를 고친다: `room = $room` → `room = ${room:sqlstring}` |
| 다중 선택 변수의 All 값이 조건과 맞지 않음(`site IN ('__all__')`) | 사용자 정의 All 값은 그대로 들어간다. `('__all__' IN ($v) OR col IN ($v))` 패턴을 쓰거나 All 값을 지운다 |
| 문자열 값만 있는 속성을 시계열 패널로 그림 | 상태 타임라인으로 옮긴다 |
| URL 의 `var-...` 에 옛 값이 고정됨 | 변수 없이 연 URL 로 다시 확인한다 |
| 쿼리 오류가 화면에 안 드러남 | Grafana 로그에서 `Partial data response error` 를 찾는다: `kubectl -n <ns> logs deploy/<grafana> -c grafana --since=1h \| grep 'Partial data response error'` |

## 주의

- 진단을 추측하지 않는다. 고치기 전에 검사 스크립트의 `error` 와 `sql`, Grafana 로그의 오류 문장을 먼저 본다.
  추측으로 한 첫 수정이 틀린 경우가 있었다.
- 사이드카가 ConfigMap 을 읽어 반영하기까지 시간이 걸린다. 사이드카 로그의 파일 쓰기 메시지나 `--wait-contains` 로
  반영을 확인한 뒤에 검사한다.
- 관리자 자격 증명은 차트가 자동으로 만든 시크릿이 아니라 values 에 지정한 시크릿에 있을 수 있다. 401 이 나면
  시크릿 이름부터 확인한다.

## 스크립트

- `scripts/panel_check.py`: 대시보드의 모든 패널(반복 패널은 값마다)의 SQL 쿼리를 `/api/ds/query` 로 실행해
  ok·empty·error 를 JSON 으로 낸다. 변수 쿼리도 실제로 실행하고, 저장된 선택값과 사용자 정의 All 값을 Grafana 처럼
  끼워 넣는다. `--admin-secret` 과 `--kubectl` 로 자격 증명을 시크릿에서 직접 읽는다. 표준 라이브러리만 쓴다. `--help` 참고.

## 하지 않는 것

- 코드로 관리하는 대시보드를 화면에서 저장하지 않는다. 다음 배포 때 덮어써진다.
- 확인하지 않은 패널을 "고쳤다"고 보고하지 않는다.
- 자격 증명을 출력하거나 파일에 남기지 않는다.
